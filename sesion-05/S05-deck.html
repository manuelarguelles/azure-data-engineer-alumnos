P.E. Data Engineer · Azure · M4S05 · 17/34

El vault y el secreto se crean una vez, no en cada clase★

# 1. Crear el vault con access policy (no RBAC)
az keyvault create \
  --name kv-pede-demo-brs-001 \
  --resource-group rg-pede-demo-dev-brs-001 \
  --location brazilsouth \
  --retention-days 7

# 2. Dar permiso al usuario que administra secretos
az keyvault set-policy \
  --name kv-pede-demo-brs-001 \
  --object-id <object-id-del-usuario> \
  --secret-permissions get list set delete

# 3. Crear el secreto sin dejarlo en el repo
az keyvault secret set \
  --vault-name kv-pede-demo-brs-001 \
  --name pede-demo-secret \
  --value "$(openssl rand -hex 16)"
  • --retention-days 7 es el mínimo de soft-delete.
  • El valor se genera en el momento: nunca se escribe en el repositorio.
  • El scope se crea después, desde Databricks o por API.

P.E. Data Engineer · Azure · M4S05 · 19/34

El notebook pide el secreto por nombre; nunca lo imprime★

# El scope no se crea en el notebook: se crea una vez en el workspace
scopes = [s.name for s in dbutils.secrets.listScopes()]
print(scopes)  # ['kv-pede']

# Leer el secreto por nombre
token = dbutils.secrets.get(scope="kv-pede", key="pede-demo-secret")

# Databricks redacta el valor en la salida
print(token)        # [REDACTED]
print(len(token))   # la longitud sí es visible
  • Nunca se escribe el valor en una celda ni en un archivo.
  • La redacción no protege de transformaciones deliberadas: no conviertas el secreto en otra cadena.
  • El permiso se da al scope, no al notebook.

P.E. Data Engineer · Azure · M4S05 · 23/34

Una consulta crea la tabla Delta sin mover los CSV★

CREATE OR REPLACE TABLE pede.bronze.orders
USING DELTA
LOCATION 'abfss://bronze@stpededemobrs001.dfs.core.windows.net/delta/orders'
AS
SELECT *,
       'abfss://bronze@stpededemobrs001.dfs.core.windows.net/pedidos/fecha_carga=2026-10-10/orders.csv' AS _source_file,
       '2026-10-10' AS _load_date,
       current_timestamp() AS _ingested_at
FROM read_files(
  'abfss://bronze@stpededemobrs001.dfs.core.windows.net/pedidos/fecha_carga=2026-10-10/orders.csv',
  format => 'csv', header => true, inferSchema => true
);
  • read_files lee el CSV desde la external location, sin copiarlo al workspace.
  • LOCATION deja los archivos Delta en el lago.
  • Las columnas de auditoría permiten reconstruir el origen.

Cinco preguntas de salida

¿Cuándo conviene un clúster clásico y cuándo serverless?

Clásico cuando controlas tamaño y runtime y tienes cuota; serverless cuando no hay cuota o el trabajo es intermitente.

¿Qué pieza de UC autoriza una ruta del lago?

La external location, usando una storage credential respaldada por el access connector.

¿Para qué sirve Key Vault si el lago se accede por identidad?

Para secretos de aplicación, como la contraseña de Azure SQL que usará ADF.

¿Qué diferencia hay entre tabla managed y external?

Managed guarda los archivos en el storage del catálogo; external apunta a una ruta del lago.

¿Cómo pruebas que la carga bronce quedó bien?

Conteos 5/8/10/15/9, tabla External en formato Delta e historial con la operación de carga.
