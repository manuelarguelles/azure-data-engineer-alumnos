Bloque 1 · Los datos no son todos iguales

25 minutos · qué es un esquema y por qué decide el servicio

P.E. Data Engineer · Azure · M2S02 · 5/60

Un esquema es una promesa sobre las preguntas que vas a poder hacer★★

  • Declara qué campos existen, de qué tipo son y qué relaciones son válidas.
  • Estructurado: el esquema se impone antes de escribir (schema-on-write).
  • Semiestructurado: el esquema viaja con el dato y se interpreta al leer (schema-on-read).
  • No estructurado: no hay campos; hay metadatos y modelos que extraen significado.
  • La pregunta de negocio manda: si no puedes describir la consulta, todavía no puedes elegir el motor.
P.E. Data Engineer · Azure · M2S02 · 6/60

Schema-on-write valida al guardar; schema-on-read valida al consultar★★

Schema-on-write · SQL

CREATE TABLE pagos (
  payment_id INT PRIMARY KEY,
  order_id   INT NOT NULL,
  amount     DECIMAL(10,2) NOT NULL,
  method     NVARCHAR(20) NOT NULL
    CHECK (method IN ('tarjeta','efectivo','transferencia'))
);

-- Falla al insertar: monto no numérico
INSERT INTO pagos VALUES (99, 1001, 'trece', 'yape');
  • El contrato se declara antes del primer INSERT: tipos, nulabilidad, claves y CHECK.
  • Un dato inválido no entra: el error aparece en la escritura.
  • Ventaja: toda consulta futura puede confiar en el tipo.
  • Costo: cada cambio de forma exige ALTER TABLE y decidir qué hacer con la historia.

Schema-on-read · JSON

{
  "paymentId": 99,
  "orderId": 1001,
  "amount": "trece",
  "method": "yape",
  "extra": { "cuotas": 3 }
}

// El documento entra; la regla se aplica al leer
db.pagos.find({
  amount: { $type: "number" },
  method: { $in: ["tarjeta","efectivo"] }
})
  • El documento se guarda tal como llega; el esquema vive en el código que lo interpreta.
  • Un dato inválido entra y se descubre en la lectura o en un reporte.
  • Ventaja: un campo nuevo no obliga a migrar los documentos viejos.
  • Costo: la validación se repite en cada consumidor y la deuda de calidad crece.
P.E. Data Engineer · Azure · M2S02 · 7/60

Estructurado: filas, columnas y una respuesta exacta★

  • Ejemplos: facturación, pedidos, pagos, reservas, planillas de ERP.
  • Cada fila cumple el mismo contrato; cada columna tiene un tipo declarado.
  • Consultas exactas con filtros, JOIN y agregaciones (SUM, COUNT, AVG).
  • Integridad transaccional: una venta se registra completa o no se registra.
  • El costo: cambiar el esquema duele y una columna mal tipada contamina años de reportes.
P.E. Data Engineer · Azure · M2S02 · 8/60

Semiestructurado: el dato trae su propio esquema★

  • Ejemplos: eventos JSON de la web, logs, APIs, XML, CSV con columnas variables.
  • El esquema se valida al leer, no al escribir; dos eventos pueden tener campos distintos.
  • Permite evolucionar sin migrar toda la tabla, pero exige reglas de validación explícitas.
  • Se consulta con funciones de JSON, motores de documentos o procesamiento distribuido.
  • El riesgo: 'parece gratis', pero la validación y la calidad se pagan en cada lectura.
P.E. Data Engineer · Azure · M2S02 · 9/60

No estructurado: el significado no está en columnas

  • Ejemplos: imágenes, audio, video, PDF, contratos, correos, señales de sensores.
  • Caso adicional: una llamada de call center. El audio es el dato; la transcripción, el resumen y el motivo de contacto son extracciones que se validan antes de consultarse.
  • Se guarda como binario o texto libre; lo consultable son sus metadatos.
  • El valor se extrae con OCR, visión, transcripción, NLP o modelos de embeddings.
  • La plataforma típica es almacenamiento de objetos o un data lake, no una base transaccional.
  • El riesgo: costo variable y resultados probabilísticos; hay que medir calidad, no solo latencia.

Clasificar es decidir dónde puede vivir y cómo se consulta

  • 1. ¿La pregunta exige exactitud, relaciones y auditoría? → estructurado, motor relacional.
  • 2. ¿El esquema cambia por evento y consultas por una clave? → semiestructurado, motor de documentos.
  • 3. ¿El contenido es binario o texto libre? → no estructurado, almacenamiento + metadatos + modelo.
  • Clasificar por la extensión del archivo es un error: un CSV puede ser estructurado o solo un contenedor de eventos.
  • Escribe la decisión: tipo, pregunta, servicio candidato y supuesto que la sostiene.

P.E. Data Engineer · Azure · M2S02 · 16/60

Azure SQL Database es SQL Server administrado: tú gobiernas el dato, Microsoft la infraestructura★

  • Mismo motor y mismo T-SQL que SQL Server; las consultas y el esquema no cambian.
  • PaaS: Microsoft aplica parches, hace backups y sostiene la alta disponibilidad.
  • Tú gobiernas esquema, índices, permisos, consultas y costo.
  • No administras sistema operativo, disco ni máquina virtual.
  • Opciones: base única, pool elástico y managed instance; hoy usamos base única.

La consulta de negocio cruza cuatro tablas y responde una pregunta

SELECT c.full_name, p.method,
       SUM(oi.quantity * oi.unit_price) AS total
FROM customers c
JOIN orders o       ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
JOIN payments p     ON p.order_id = o.order_id
WHERE o.status = 'pagado'
GROUP BY c.full_name, p.method
ORDER BY c.full_name, p.method;
  • Pregunta: ¿cuánto pagó cada cliente por método de pago?
  • Resultado esperado: ocho filas y un total de 13.158,50.
  • Si el total no da 13.158,50, revisa el JOIN con payments y el estado del pedido.

P.E. Data Engineer · Azure · M2S02 · 44/60

Gremlin y Table: grafo y clave-valor, no documentos★★

Gremlin modela relaciones y las recorre como un grafo; Table guarda entidades por clave. Ninguno de los dos es un documento JSON.

P.E. Data Engineer · Azure · M2S02 · 45/60

Contenedor = documentos + una clave de partición★

  • Jerarquía NoSQL: cuenta → base → contenedor → ítems (documentos JSON).
  • La jerarquía cambia de nombre según la API: MongoDB base → colección → documento; Cassandra keyspace → tabla → fila; Gremlin grafo → vértice/arista; Table tabla → entidad.
  • La clave de partición es obligatoria y define cómo se reparten los datos.
  • El id es único dentro de la partición, no en todo el contenedor.
  • La política de indexación y las RU/s se configuran por contenedor.
  • Una consulta sin la clave de partición recorre todas las particiones y consume más RU.
P.E. Data Engineer · Azure · M2S02 · 46/60

La clave de partición se elige una vez y se paga para siempre★

  • Cardinalidad = cantidad de valores distintos. Alta: customerId (miles), deviceId, orderId. Baja: status (4 valores), country, channel.
  • Busca alta cardinalidad y distribución uniforme: customerId, tenantId, deviceId.
  • Evita valores con pocas categorías y alta concentración: status, country en un negocio local. Con 4 estados, todas las escrituras caen en 4 particiones.
  • La clave debe aparecer en las consultas frecuentes para evitar el barrido de particiones.
  • Es inmutable: cambiarla obliga a reescribir los datos.
  • Límite lógico de 20 GB por partición: una clave caliente te pone techo antes de tiempo.

Repaso de 60 segundos: servidor lógico, base y firewall

Servidor lógico

  • Nombre DNS único: <nombre>.database.windows.net.
  • Agrupa logins, reglas de firewall y varias bases.
  • No contiene tus tablas ni tu esquema.

Base de datos

  • Contiene esquema, tablas, usuarios y datos.
  • Tiene capa de servicio, backups y límites propios.
  • El firewall se configura en el servidor, no en la base.
P.E. Data Engineer · Azure · M2S02 · 56/60

Cinco preguntas de salida

¿Qué diferencia hay entre servidor lógico y base de datos?

El servidor agrupa administración y red (login, firewall); la base contiene esquema, datos y rendimiento.

¿Un evento JSON con campos variables es estructurado o semiestructurado?

Semiestructurado: el esquema viaja con el evento y se valida al leer.

¿Qué pasa si consultas Cosmos DB sin incluir la clave de partición?

Se consultan todas las particiones (fan-out): funciona, pero consume más RU y agrega latencia.

¿Cuándo NO usarías Cosmos DB?

Cuando necesitas integridad referencial, JOIN y agregaciones exactas sobre datos transaccionales.

¿Qué tres números validaste en el laboratorio?

Los conteos por tabla, el total pagado 13.158,50 y las ocho filas de la consulta.
